# 个人介绍站点方案

写于 2026-10-19。注册前以各服务官网当时的页面为准，规则会变。

## 结论

做**一份静态个人介绍页**，用两个入口打开同一份页面：

| 角色 | 地址 | 什么时候用 |
| --- | --- | --- |
| 现在就发出去的主链接 | `你的名字.github.io` | 今天就能点开，不审核、不续费 |
| 想要独立名字时的第二入口 | `你的名字.cn.eu.org` | 申请通过后再挂上，不挡上线 |

主链接选 GitHub Pages，是因为免费方案里它最接近「一直能打开」：地址跟你的 GitHub 账号走，自带 HTTPS，页面是静态文件，不需要服务器。`cn.eu.org` 是 1996 年就在发的免费名字，不按年收费，但要人工审核，时间不可控，所以只做加分项。

名片、签名、作品集先只印 `github.io`。第二入口下来之后，再决定要不要换成它。页面不用重建。

## 「永久免费域名」实际是什么

不存在既免费、又归你永久所有的顶级域名。你真正拥有的名字（`.com`、`.me`、`.design`）都要向注册局付年费。免费能拿到的，是下面两种：

- **平台主机名**：例如 `名字.github.io`。平台在，地址就在。你离开平台，地址就没了。
- **别人域名下的免费名字**：例如 `名字.cn.eu.org`、`名字.is-a.dev`、`名字.pp.ua`。不收注册费，但名字的存续取决于运营方还在、你还守规则。运营方可以回收，你也不能把它转到任意注册商名下当成自己的资产。

`.tk`、`.ml`、`.ga`、`.cf`、`.gq` 的免费注册已经结束。看到「免费顶级域名」的广告，直接跳过。

这里的「永久」只表示：**不收年费，而且不靠你每年记得去点续期。** 它不等于产权。

## 为什么是这一套

个人介绍页的要求很窄：一个地址，点开就是你是谁、做什么、怎么联系。它不需要数据库，不需要登录，也不该绑在一个随时可能停服的免费主机上。

所以拆成两层：

1. **页面**：一个公开的 Git 仓库，GitHub Pages 直接发布。改字、换图，推上去就更新。
2. **名字**：先用仓库自带的 `用户名.github.io`。想要不带 GitHub 字样的地址时，再把免费名字的 DNS 指到同一份页面。

这样最坏的情况是第二入口失效，主链接还在，内容还在。

`cn.eu.org` 放在第二位，是因为 EU.org 从 1996 年做到现在，目标就是给付不起域名年费的个人和非营利项目一个名字，而且**不做按年续费**。中国有独立委派 `cn.eu.org`，申请写在这一层，比直接抢 `eu.org` 根上的短名字更容易被接受。代价是地址偏长，而且他们只做域名服务器委派（NS），自己不托管解析，DNS 要用别处的免费服务来接，Cloudflare 的免费套餐就够。

## 其他免费名字，这次不用

| 名字 | 形态 | 不用的原因 |
| --- | --- | --- |
| `名字.pp.ua` | 看起来最像独立域名，注册快 | 免费，但**每年都要续**，续的时候还要用手机号激活。忘了，过了宽限期就要付费赎回，而且不保证赎得回。WHOIS 公开手机号，藏不了。 |
| `名字.is-a.dev` | 开发者常用，提一个 GitHub PR | 适合给程序员看的地址。个人站可以用，长时间不更新可能被收回。它是志愿者项目，不是注册局。注册前先看仓库是否还在收 PR。 |
| `名字.js.org` | 很干净 | 现在不发给和个人介绍、作品集没有明确 JavaScript 关系的页面。 |
| `名字.runs-on.dev` | 用 GitHub 登录就能领 | 官方说明写了：闲置可收回，不适合「必须比这个项目活得更久」的名字。 |
| `名字.pages.dev` / `名字.netlify.app` / `名字.vercel.app` | 跟着托管平台走 | 能用，但离开该平台地址就没了，不如 `github.io` 稳。 |

如果以后这个地址要印在长期使用的名片上，而且你在意别人第一眼觉得它像自己的品牌，就买一个真域名，指到同一份 GitHub Pages。页面仍然不用重做。那是另一笔每年几十块的花费，不在这次免费方案里。

## 页面本身

一页就够。打开后先回答三件事：你是谁，你做什么，怎么找到你。作品放在这三件事后面，不要做成后台系统。

建议结构：

1. **名字和角色**  
   一行名字，一行角色。角色用你希望对方记住的说法，例如「产品设计师，做工具和品牌」。不要堆职称。
2. **一句现在**  
   你现在在做什么、想被怎样找到。两行以内。
3. **代表作，最多三件**  
   每件：一张图、项目名、一句话结果、一个链接。没有链接的就不要放。宁缺三件里的一件，也不要放凑数的练习。
4. **联系**  
   只留你真的会看的渠道。一个邮箱足够。其余社交如果三个月内不会回，就不要放。
5. **页脚**  
   写主链接 `你的名字.github.io`。第二入口生效后再决定要不要改成它。

排版原则：

- 手机上第一屏必须能看完名字、角色和那一句现在。作品往下滚。
- 黑白或一种强调色。个人介绍页的第一印象来自留白和字体，不来自动效。
- 图片要压过体积。整页应在普通手机网络下几秒内打开。
- 只做中文，或中文在上、英文一行角色在下。不要做语言切换，除非你确实有两套要维护的介绍。

文案留空，等你自己的事实填进去。名字、角色、三件作品、邮箱，这四项齐了就可以上线，不必等第二入口。

## 落地顺序

名字先定死。域名只用小写拉丁字母和连字符，尽量就是你希望被人叫出来的那个英文名或拼音，短、好拼、和真名一致。定了就不要为了「更好听」来回改，GitHub 用户名一改，主链接会跟着变。

1. **GitHub 上建一个公开仓库**，仓库名用 `用户名.github.io`。打开 Pages，源选该仓库的主分支根目录。得到 `https://用户名.github.io`。
2. **先放一页能发出去的介绍**，按上面的五段结构。图片放在仓库的 `assets/`。确认手机上第一屏是名字和角色。
3. **把这个 `github.io` 发给自己，在另一台设备上点开。** 能打开、字是你自己的、联系方式点得通，这一步就完成了。
4. **并行去申请 `你的名字.cn.eu.org`，不等它。**  
   入口是 [nic.eu.org](https://nic.eu.org/)。`cn.eu.org` 由 EU.org 这边受理（站点上单独列出的、要去别的服务器申请的国家委派，不要走错）。他们只接受 NS 委派：先在 Cloudflare 免费套餐里加上这个名字，拿到 Cloudflare 给的两台域名服务器，再把这两台填进申请。审核可能是几天，也可能很久。被拒就继续用 `github.io`，不换方案。
5. **申请通过之后再接线。** 在 Cloudflare 里把该名字指到 `用户名.github.io`（DNS only，灰色云朵，证书交给 GitHub Pages）。再到仓库的 Pages 设置里填上这个自定义域名，等 HTTPS 生效。用浏览器无痕窗口点一次 `https://你的名字.cn.eu.org`，确认看到的是同一份介绍。
6. **两个地址都活着以后，再决定名片印哪一个。** 在那之前只印 `github.io`。

EU.org 不提供使用支持。申请说明以他们站点上的 policy 和开放域名列表为准。Cloudflare 账号用你自己的邮箱注册，开启登录验证。

## 风险，接受了再做

- `github.io` 绑定 GitHub 用户名。改用户名，主链接改变。GitHub 会保留一段时间的跳转，但印出去的材料要跟着改。
- `cn.eu.org` 不是你的财产。EU.org 停服、收回，或你违反他们的使用政策，这个入口会消失。页面因为在 GitHub 上，还在。
- 免费 DNS 和免费页面都依赖这两家公司的免费额度。个人介绍页的流量远在额度之内。
- 不要把密码、证件号、家庭住址写进页面或仓库。仓库是公开的。

## 做完的标准

- 把 `https://用户名.github.io` 发给一个没看过这个项目的人，对方不用登录、不用翻仓库，就能看到你的名字、角色、至少一件作品和一种联系方式。
- 手机和电脑都能打开，地址栏是锁形的 HTTPS。
- 你知道第二入口是加分项：它没下来之前，这个站点已经算完成。
